# Pi Agent 1.0.2 → 1.5.0 升级报告

- 日期：2026-11-05
- 基线：`ae78f5e8f0c9060c51d9a22ae0d9e9c6f9e48021`
- 升级分支：`codex/pi-1.5-upgrade`
- 旧版本：`@earendil-works/pi-coding-agent@1.0.2`
- 新版本：`@earendil-works/pi-coding-agent@1.5.0`

## 1. 结论

Pi Agent 已升级到最新稳定版 `1.5.0`。生产代码仍通过既有 `customTools + noTools:
"builtin" + registerTool + setActiveTools` 装配工具；审批和执行权威仍在 Sparkii Main。

本次采用“等价升级”：

- 采用 Pi 1.5 的运行时修复、流式性能、Windows 路径/凭据锁修复和会话写入修复；
- 适配 `before_agent_start` union、`pi-schema` 工具验证和 Kimi Coding 端点；
- 不启用 codemode、MCP、tool-search、virtual models、Pi cache warmer 或 Pi 自更新器；
- 关闭 Pi 内部图片 auto-resize，继续由 Sparkii Main 的 `nativeImage` 负责附件压缩。

## 4. 兼容处理

### 4.1 `before_agent_start`

1.2.0 起事件分为 `user` 和 `custom`。Sparkii 新增
`projectSaddlePromptInput()`，只读取两类事件共有的 `systemPrompt` 与
`systemPromptOptions`，不读取用户事件独有的 `prompt`。

回归测试覆盖：

- user/custom 两种事件；
- options 缺失时仍从 `systemPrompt` 保留 `<available_skills>` 和 cwd；
- 读取 `prompt` 会抛错的对象不会导致 handler 失败。

### 4.2 工具 loadout 与会话恢复

Pi 1.3 会从 transcript 恢复活动工具。Sparkii 在 `switchSession()` 后重新应用当前 saddle，
测试先写入一个声明 `bash` 的 v3 会话，再断言恢复后的活动工具只剩当前 saddle 的 `read`。

以下不变量保持：

- 不在会话创建时冻结 `tools` 白名单；
- `noTools: "builtin"` 关闭内置工具自动激活；
- 未知工具 fail closed；
- `codemode` 和 `tool_search` 不出现；
- 新会话、切换会话和换鞍后工具集合都精确匹配。

### 4.3 `pi-schema`

1.5 把工具参数验证统一到 `@earendil-works/pi-schema`。Sparkii 使用同版本
`@earendil-works/pi-ai@1.5.0` 作为测试开发依赖，直接调用公开
`validateToolArguments()` 验证：

- missing required；
- `additionalProperties: false`；
- 数字字符串 coercion；
- 单值到数组 coercion；
- error path/message；
- 连接器 proposal 收到验证后的参数副本。

`jsonSchemaToTypeBox()` 现在保留 `description/default/minimum/maximum/additionalProperties`
和 `integer`，继续使用原有的 required 默认规则。

### 4.4 Kimi Coding

Pi 1.3 的 Kimi Coding 新端点为 `https://api.kimi.com/coding/v1`。Sparkii 仅在 provider id
为 `kimi-coding` 且 URL 精确为 `https://api.kimi.com/coding` 或尾斜杠形式时规范化。

规范化同时作用于 `settings.json` 读写、provider 目录和 `models.json` 写入；其他 host/path
不改写。

### 4.5 图片输入

Sparkii Main 已在发送图片前用 Electron `nativeImage` 完成尺寸和大小压缩。Pi 内部的
`imageAutoResize` 被显式关闭，因此不会进入 `image-resize-worker.js` / Photon WASM 动态路径。

本报告不把 Pi 内部图片自动缩放声明为支持能力；未交付的 worker/WASM 也未被打包。
PNG/JPEG/GIF/WebP 由 Sparkii 附件入口和图元转换路径处理。

### 4.6 会话格式

`CURRENT_SESSION_VERSION` 仍为 `3`。新增测试在当前 1.5 读取路径中 round-trip `usage`、
`custom` 和 `context_edit` 等可选条目。

该测试证明当前读取器能处理 1.5 的 version-3 扩展条目，不等同于用 1.0.2 二进制实际打开
1.5 文件。由于版本号未变、核心 entry 形状兼容，回滚风险低；升级报告不宣称已完成
1.0.2 实读交叉验证。

## 6. 回滚

- 升级改动集中在 `codex/pi-1.5-upgrade` 分支，可按提交回滚。
- 会话版本未变，不需要数据迁移。
- 回滚到 1.0.2 时，1.5 写入的可选 JSONL 字段和 Pi settings 新字段可能保留；旧版本应忽略未知字段。
- Kimi 规范化后的 `/coding/v1` 是当前官方端点，不需要回退到旧地址。
- 回滚后仍需使用 1.0.2 自身再跑一遍完整测试；不要把本轮 1.5 测试当作 1.0.2 回滚证明。
