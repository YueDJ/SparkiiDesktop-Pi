## 1. 必须改的东西（按风险分级）

> 本节已并入架构师第 1 轮评审（`architect-review-round1.md`，裁定**有条件通过**）的 C1/I1/I2/I5 修订，
> 修订点用 `[rev2]` 标出。

### B0（阻断级）[rev2] 1.0.2 SDK 路径默认开启 prompt cache warming

`pi-1.0.2` 新增 `core/cache-warmer.js`（0.84.4 无此文件），且 SDK 路径**无条件**接上它：

- `core/skd.js:180`：`new CacheWarmer(modelRuntime, sessionManager, () => settingsManager.getCacheWarmingMode(), …)`；
- `core/sdk.js:258`：每次请求 `cacheWarmer.start({ model, context, options }, …)`；
- `core/settings-manager.js:680-681`：未设置时 `getCacheWarmingMode()` 返回 **`"streaming"`**（不是 off）；
- `core/cache-warmer.js:238-249`：刷新 = 对 provider 再发一次 `streamSimple(..., maxTokens: 1)` 的**额外计费请求**，
  并 `sessionManager.appendUsage("cache_warm", …)` 往 JSONL 追加一条 `usage` 条目。

触发门槛是"模型目录里有 `promptCache` TTL + 可重放 + 预期节省 ≥ $0.05"。本仓库 `models.json` 只写自建 provider
（`pi-model-config.ts`），但一旦配置了带 promptCache 元数据的内置 provider（Anthropic/OpenAI 系），
就会在 run 期间多发计费请求 —— 这与本计划第一目标"不改变现有产品行为"直接冲突。

修法：升级后把 `"cacheWarming": "off"` 显式写进 **Pi 的 agentDir** 的 `settings.json`
（= `dataDir/pi-agent/settings.json`，不是 AppSettings 的 `dataDir/settings.json`，
见 `apps/desktop/electron/main/runtime.ts:153,168` 与 `apps/desktop/electron/main/settings.ts:42-56`）；
并在验收里断言 `settingsManager.getCacheWarmingMode() === "off"` / `session.cacheWarmingStatus?.state === "inactive"`。

### B1（阻断级）工具装配绕过了 1.0 的 loadout 闸门

现状：`packages/agent-host/src/pi-sdk-runtime.ts:260` 直接写
`session.agent.state.tools = saddleTools`，工具定义由 `resolveToolDefinitions()` 现造。

1.0 的变化：

- `AgentSession` 内部新增**权威工具注册表** `_toolRegistry`（`agent-session.js` 构造时由 `customTools` + 扩展注册的 tool + 内置 tool 组成）。
- 每次 prompt 都会走 `_preparePromptAndToolLoadout()` → `_applyToolLoadout(selectedTools)`，
  该方法**只保留 `_toolRegistry` 里存在的名字**，然后 `this.agent.state.tools = declared`。
- 0.84.4 里这两个方法存在但**没有任何调用点**（`Select-String` 在 0.84.4 上 0 命中，在 1.0.2 上有 4 处），
  所以"事后直接赋值 `agent.state.tools`"在 0.84.4 能生效，在 1.0.2 会被 prompt 路径重新推导覆盖。

后果若不动：模型在 1.0.2 下**看不到鞍里的任何工具**（`bash/edit/write`、连接器工具全部失效），
而 `configure_session` 仍返回成功 —— 静默失效，最危险的一种。

修复方向（架构师 R1 裁定后固定）：

1. **首选（[rev2] 选项名已更正）**：在 `createRuntime` 内（此处已持有 `saddle`）调用
   `createAgentSessionFromServices({ …, customTools: saddleTools, tools: saddleToolNames })`。
   两个选项**必须成对传**：`core/sdk.js:302` 的 `usesDefaultTools = options.tools === undefined && !options.noTools`，
   只传 `customTools` 会让默认内置工具（read/bash/edit/write）重新激活 ⇒ 鞍外工具静默出现。
   `tools` 同时决定 `allowedToolNames` 与 initial active（`core/sdk.js:145`）。
   会话中途换鞍：`pi.registerTool()`（同名覆盖，`_refreshToolRegistry:2795-2828`）+
   `pi.setActiveTools()`（`extensions/types.d.ts:1254`），必要时 `session.reload()`。
   `allowedToolNames` / `initialActiveToolNames` 是 AgentSession 的**内部 config 字段**，不是 SDK 选项 —— 不要照抄。
2. **兜底**：换鞍时重建会话（`runtime` 已有 `newSession/switchSession`），验收必须附"历史不丢（`getBranch()` 连续）+
   不额外产生/切换 jsonl 文件"的证据。
3. **禁止**：触碰 `session._customTools`（私字段，改它不会自动重算注册表，且随版本易碎）。

新增回归测试（离线可跑，不需要 provider）：断言"鞍里的工具名出现在 `session.getActiveToolNames()`"，
并且源码级断言 `pi-sdk-runtime.ts` 不再直接写 `agent.state.tools`。

### B2（阻断级风险）`build:main` 的 esbuild 打包

`apps/desktop/package.json` 的 `build:main` 用 esbuild 把
`electron/pi-runtime/utility-entry.ts` 打成**单文件** `dist-electron/pi-runtime/utility-entry.js`；
`apps/desktop/electron-builder.yml` 的 `files:` 只打包 `dist/**`、`dist-electron/**`、`package.json`，
**不打包 node_modules** —— 也就是说 Pi SDK 必须被完整内联进 bundle。

1.0.2 的包根 `dist/index.js` 会 **eager re-export** `extensions/codemode`、`extensions/mcp`、
`extensions/tool-search`，其中 `codemode/tool.js` 静态 import `@earendil-works/pi-codemode/declarations`、
`codemode/execute.js`（通过 `execute.lazy.js` 动态 import，esbuild 仍会内联）import `quickjs-wasi` 与
`getQuickJSWasmPath()`。0.84.4 没有这条依赖链。

风险：bundle 体积膨胀、esbuild 处理 `.wasm`/worker 报错、或运行期找不到 `quickjs.wasm`。
注意 SDK 路径**不会自动加载** codemode/MCP（见 1.0.2 `docs/sdk.md`：SDK 需自行把
`createCodemodeExtension()` 等加进 `extensionFactories`），所以功能上不需要它们，只需要让构建通过。

实施要求：先做一次风险探针（装上 1.0.2 后直接跑 `pnpm --filter @sparkii/desktop run build:main`）。
[rev2] 降级手段优先级（架构师 R2 裁定）：

1. **直接 bundle**（默认，先证明能过）；
2. **alias/stub 这 3 个扩展入口** —— 有静态引用证据：它们只被 `dist/index.js:34-36` 与 `dist/main.js:39` 引用，
   `core/resource-loader.js`/`core/agent-session.js` 都不静态 import 它们，而 SDK 路径永不加载/执行 codemode/MCP；
   stub 可一次剔掉 codemode/MCP/tool-search/quickjs 链路（也顺带消掉运行期 wasm 隐患）；
3. `--external`（注意 node_modules 不随包发布，"永不激活"会变成硬编码假设）；
4. 打包排除 + `extraResources`（最重、最易漏文件）。

补充事实（[rev2] I5）：`getQuickJSWasmPath()`/`getCodemodeWorkerSpecifier()` 走运行期
`createRequire().resolve()`，**不在构建期**被 esbuild 解析；构建期真正的负担只有
`codemode/tool.js:24-25` 的静态 import 与 `execute.js:9`。

探针必须记录：esbuild 实际解析到的 SDK 路径与版本（[rev2] O3：`apps/desktop` 未声明该依赖，靠 pnpm 提升解析）。

### B3（行为级）[rev2] 会话落盘门槛变化（因果方向已更正）

实测结论：0.84.4 的门槛是 **首条 assistant 消息**（`session-manager.js:729 hasAssistant`），
1.0.2 放宽为 **user 或 assistant**（`session-manager.js:791-793 _hasConversation`）。
也就是说 1.0.2 是**更早**落盘：用户发了消息但首轮未完成时，磁盘上会多出一个"半截会话"，
`SessionManager.listAll` 会列出它，`firstMessage`/`messageCount` 口径与旧版不同。

需要实测确认的新边界（不是"空会话会不会不再落盘"，那在 0.84.4 就已经如此）：
半截会话出现在列表/续跑路径（`session-catalog.ts`、`ChatSessionStore.piSessionFile`、`ipc.ts` 的 4 处读取、
`workflow.ts:382`、"工作流首轮未完成就退出"）时的行为是否符合预期。
另需确认 JSONL 新增的 `usage`/`cache_warm` 条目在 `readPiSessionEntries`/live normalize 里不会被渲染成异常行。

### B4（行为级）`before_agent_start` 的强制系统提示投影

1.0 把"handler 返回 `systemPrompt`"改成**投影到请求头部**而不是追加 mid-conversation 系统消息
（`_installAgentForcedPromptProjection`），并且 `BeforeAgentStartEvent.systemPromptOptions` 的类型从
`BuildSystemPromptOptions` 收紧为 `NormalizedBuildSystemPromptOptions`。
本仓库 `skill-prompt.ts` 依赖 `systemPromptOptions.skills / selectedTools / cwd`，
`pi-sdk-runtime.ts` 的 `systemPromptExtensionFactory` 会把 `workspaceRoot` 塞进该对象。
需要验证：`<available_skills>` 目录仍会出现在最终提示里（有既有测试
`pi-sdk-runtime-skill-rebind.test.ts`、`skill-prompt.test.ts`），且 `workspaceRoot` 不再被
excess-property 检查或运行时归一化丢弃。1.0 还有 `context_with_system` 事件，必要时改用。

### B5（低风险，需确认）SDK 不自动加载 codemode/MCP/工具搜索

1.0.2 `docs/sdk.md`：CLI 加载 `codemode`/`tool_search`/MCP 为内建扩展，**SDK 会话不加载**。
我们走的是 SDK 路径且从不加这些扩展，所以"模型工具面"应保持不变；此点需要在 B2 的探针里顺带确认
（bundle 能被 import、会话能创建、工具名集合与 0.84.4 一致）。

### B6（配置与迁移）

- `runMigrations()`（auth/models 迁移）只存在于 **CLI 入口**；SDK 路径不会自动跑。
  仓库自己写 `models.json`（`pi-model-config.ts`）与 `auth.json`/`setRuntimeApiKey`，
  需要确认 1.0.2 的 `ModelRuntime.create({authPath, modelsPath})` 对这两份文件的格式没有新增必填字段
  （1.0.2 新增了 `samplingParamsByThinkingLevel`、`virtual-models`、`deviceId` 等，均为可选）。
- `settings.json` 新增 `codemode`、`cacheWarming`、`quietStartup:"header"`、`fullscreenWheelScrollLines`、
  `deviceId`；`tuiMode` 默认变 fullscreen（**只影响 TUI，不影响 SDK 子进程**）。
  仓库只在子进程里用 SDK，`settings.json` 由 Pi 自行读写，需确认不会因为缺字段而告警或写入破坏性内容。
- `ModelRuntime.refresh()` 的返回结构 `{aborted, errors: ReadonlyMap}` 在 pi-ai 1.0.2 仍存在
  （已核对 `pi-ai-1.0.2/dist/models.d.ts:38`），`pi-sdk-runtime.ts` 的 `listModels()` 无需改动。
