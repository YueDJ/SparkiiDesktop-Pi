# 统一复审结论

## 一、知识库 UI 设计评审

**与代码一致性**：事实引用基本准确（向导③勾选 `index.tsx:619,642-656`、创建时 setSessionKnowledge + 写 project.json `:363-366,393-397`、准备阶段只读文字 `:714`、数据源 `listRagDatasets→listDatasets()`）。但发现两处实质偏差：mockup 写死库名（真实来自 RAG 后端动态返回）；降级提示只设计了向导、漏了准备阶段；空绑定态需传空数组而 `setSessionKnowledge` 无专用清空语义。

**技术可行性（准备阶段更换需要的改动）**：
1. 新增 workbench 侧 dataset 加载（`ragDatasets` 现在仅 wizardOpen 时加载）；
2. 从 `activeProject.knowledgeBases` 派生当前选中态；
3. 提交时同时调 `setSessionKnowledge` + `writeProject` + 刷新 state；
4. T1 索引不受影响（T1 只索引 `input/`，与 RAG 无关）；
5. **硬伤**：`sessionKnowledgeSelections` 是内存 Map，重启即失；需增加"从 project.json 恢复绑定"逻辑；
6. **F8**：多 session 共享 workspacePath 时绑定是 per-sessionId，需定义同步模型。

**RAG 知识库 vs 项目私有资料**：有区分意识但需明说是两条独立通道（一个外部 RAG + 内存绑定，一个落盘 input/ + T1 索引）。

**交互/状态问题**：
- 原型勾选/× 只改前端，从不开 API —— 需补提交语义；
- 草稿态/已绑定态未区分，未确认离开会静默丢失 —— 需"应用/取消"提交语义与回滚；
- 空绑定态、无连接降级文案、× 删除生效时机需明确。

**生命周期一致性**：原设计"写作后显示绑定但锁定更换"与代码不符（drafting 后整个 setup 面板不渲染，是"入口消失"）；需与方案 C 统一为同一措辞。设计稿 chips"零新增业务特判"与新增 relocateWorkspace IPC 矛盾。

## 二、技术验证结论复核

**MUST-FIX 3 推翻成立，证据充分**：本机实验证实 cwd 锁目录（EBUSY）；代码核对切中要害（Pi fork 不设 cwd、saddle.cwd 指向 app data、configureSaddle 不 chdir）。

**验证盲区**（不阻塞）：未验证 F8 共享 workspacePath 下其他 session 是否有 sandbox helper 在跑；未覆盖 fs.cp 递归期间源被占用。二者均被"末位删源 + 失败保留双份"兜底覆盖。

**放行是否过早**：是。知识库 UI 是新增且从未评审；计划未把 B1 修复列为前置依赖；计划步骤4"不调用 end"与技术验证报告"可保留一次 end 作防御"矛盾。

### 用户验收追加修订（v2，同日）

用户验收时发现：**准备阶段面板在写作后整体消失，导致知识库绑定入口也消失，写作后无法修改**。这是原设计的真实缺陷（原方案把知识库与存放位置套用同一"写作后锁定"逻辑，但两者风险性质不同）。

修订：
- 知识库入口从"准备阶段面板内"移到**顶栏常驻**（popover，与"工作区"并列），setup / drafting / exported 全程可改。
- 准备阶段面板内改为只读摘要 +「前往设置」指引。
- 设计稿 v2：新增顶栏入口与 popover、重写交互脚本（草稿回滚、计数/摘要同步、点外部关闭）、移除"写作后隐藏入口"逻辑；决策⑦改为"顶栏常驻随时更换（含写作后）"。
- 搬迁计划 5.4 增加"知识库绑定不适用此锁定"的明确注记。
- 理由：换检索源是低风险操作，写作中途发现缺库是常见需求；改后立即对后续检索生效、不影响已写正文。存放位置（高风险搬目录）仍写作后锁定，两者生命周期分离。

### 放行状态
设计稿与计划层面的 MUST-FIX 已全部合入，用户验收发现的知识库入口问题已修订为顶栏常驻。**放行前仍需用户确认知识库 UI 设计（第 ⑦ 项，现为顶栏常驻方案）**，并明确 B1 修复与搬迁的合入顺序。
