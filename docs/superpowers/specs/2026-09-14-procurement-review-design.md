## 1. 一句话

财务组一份证据包（需求计划 + 量/价/时对照 + 可选制度库）。系统按物资编码对齐，用公布的规则出发现。模型只写成话并标依据。人在复核页采纳 / 忽略 / 升级后导出。v1 不自动放行。

## 2. 和合同审核的差别（不要抄成「上传一个文件」）

| | 合同审核 | 财务采购审核 |
|---|---|---|
| 被审件 | 一份合同 | 一份物资需求计划（多行） |
| 对照物 | 法规 / 范本（知识库） | 本厂库存、领用、成交、在途（表） |
| 制度 | 藏在检索里 | 准备页下拉：默认 / 不使用（v1 不切多库） |
| 第一屏 | 上传合同 | 准备：计划 → 三张对照卡 → 制度 |
| 结论页 | 左原文右风险 | 上表 + 量/价/时（+ 合规）同列卡片 |
| 人的动作 | 确认 / 忽略 / 升级 | 同一套，文案是 **采纳 / 忽略 / 升级** |

## 3. 三页、一套窗体

视觉与交互以 `procurement-review-v1.html` 为准。三页共用：

1. 页外标题「财务采购审核」+ 一句说明「审核需求计划的数量、单价、时点与程序合规。」
2. 顶栏步进：**准备**（计划与对照）→ **分析**（生成结论）→ **复核**（确认意见）
3. 壳内顶栏：智能体名、当前计划摘要、量 / 价 / 时 / 合规四枚状态芯片
4. **中间滚动，顶栏与底栏固定。** 不得随内容把整窗撑高。
5. 底栏门槛：左说明、右主操作。

桌面窗宽按 Sparkii 工作台（约 1280）。卡片 12px 圆角、主色 `#2563EB`、浅底，不走奢华金 / 玻璃。

稿里为演示，「完整性审核」会直接跳到复核、三维全齐才点得了「开始分析」、制度里有「集团采购办法」、获取按钮全亮。**实现按下面锁定，不以这些演示为准。** 完整性审核也走 准备 → 分析 → 复核。

## 4. 准备页

自上而下三块，左侧序号轨。

### 4.1 物资需求计划（必须）

- 范围：本月 / 上月 / 指定单号。
- **从 OA 获取** + **上传**。未接通则获取不可点，只留上传。
- 有一份即可往下。两份都有：状态「系统 + 文件」，提示「系统与文件同时对照，差异将标出。」不得默默覆盖。
- 没有计划：底栏停在「待提交」，两个分析按钮都不可点。

### 4.2 对照数据（量 / 价 / 时）

一张总条 + **获取对照数据**（一次拉库存/领用、成交、在途）。下面三张并排卡：

| 卡 | 问句 | 范围 | 获取 | 要齐什么才开 |
|---|---|---|---|---|
| 量 | 数量 | 可选：领用 30 / 90 / 180 天 | 从库存获取 | 库存 **和** 领用 |
| 价 | 单价 | 成交 6 / 12 / 24 个月 | 从 U8 获取 | 历史成交 |
| 时 | 时点 | 在途 15 / 30 / 60 天 | 从 OA 获取 | 在途 / 近窗订单 |

每卡：范围 + 获取 + 上传。拉取与上传不互斥。只上传可以开维。未接通则该卡获取不可点。

### 4.3 制度（不是对照卡）

下拉，不是拉取/上传。v1 只有两项：

- `采购制度（默认）` — 用本智能体已配置的默认制度（BM25 / 默认绑定）
- `不使用` — 合规维关闭，只做完整性

稿里的「集团采购办法」不是 v1。v1 制度检索用本智能体 `corpus.json`（BM25）。不在准备页做多库切换。

### 4.4 底栏

与逻辑稿 §6 一致：交了哪维事实，就开始评哪维。不要因为成交还没传，就把已经传的库存扔掉。

| 条件 | 完整性审核 | 开始分析 | 底栏说明 |
|---|---|---|---|
| 没有计划 | 不可点 | 不可点 | 待提交 |
| 只有计划（量价时都未开） | 可点 | 不可点 | 将只做完整性（及选用的制度） |
| 计划 + 任一对照维 | 仍可点（本跑次忽略已传对照） | 可点 | 列出将评估 / 未评估的维 |
| 计划 + 量 + 价 + 时 | 可点 | 可点 | 材料已齐 |

开始分析：只把已开维写进证据包。完整性审核：facts 传空，三维关闭。

选用制度时补一句「含程序合规」；不使用则「制度未选用」。

没有「来源未接通 / 接口已通 / 混合」页签，也没有「完整审核 / 仅计划」页签。

## 5. 分析页与复核页

两页 **同一套布局**。复核只多出处理动作和导出门槛。

### 5.1 共同结构

1. 顶栏芯片反映本次实际开了哪几维。
2. 分析页顶一条进度：对齐编码 → 完整性 → 套规则（薄路径跳过）→ 制度（未选用则跳过）→ 撰写发现。
3. 对照未交时，表上方黄条：「对照数据未提交，数量、单价、时点未评估。」
4. **需求计划表**：编码、物资、本次、库存、领用、单价、中位价、在途。未开维的格子为「—」。点行高亮对应发现。
5. 下方三张与准备页同宽的条件卡：**量 / 价 / 时**。制度选用或薄路径有完整性发现时，**同一栅格再多一列**合规（或完整性）卡，高度随内容，不得拉满整行。
6. 每条发现：维、高/中、标题、理由、建议、**依据**（必有）。没有依据的发现不准出现。未命中规则的已开维写「未命中规则。」或「无异常」，不准写假的「价格正常」。

稿中示例（实现测试夹具应对齐语义，数字可同源）：

- 烟煤覆盖约 10 个月（高 / 量）
- 烟煤偏离 18%（高 / 价）
- 镁铬砖在途仍申报（中 / 时）
- 镁铬砖偏离 11%（中 / 价）
- 烟煤单行超集采线（中 / 合规，选用制度时）

薄路径示例：一条「数量、单价、时点未评估」+ 可选合规。

### 5.2 分析页底栏

- 左：`N 行已对齐 · M 条发现`（未选制度则加「制度未选用」）
- 右：**返回准备** / **进入复核**
- 发现上 **没有** 采纳 / 忽略 / 升级

### 5.3 复核页

- 与分析页同一张表、同一组卡。
- 每条发现多：**采纳 / 忽略 / 升级**（互斥，再点同一项撤销）。写入意见单独，不替代这三项。
- 顶条：高风险是否处理完、已处理条数。
- 底栏：高风险未处理 →「高风险待处理」，**写入意见 / 导出** 不可点；处理完 →「可以写入意见」，写入后走审批再导出。
- **返回分析** 可点。

## 6. 文案

短、商务、中文。按钮以界面稿 §4 与准备页为准，至少包括：获取对照数据、从 OA 获取、从库存获取、从 U8 获取、重新获取、上传、更换文件、开始分析、完整性审核、进入复核、返回准备、返回分析、采纳、忽略、升级、写入意见、导出。v1 获取类按钮可见但不可点。

不用：采信、完整审核/仅计划（作为页内模式）、来源模式页签、价格正常（无命中时）。

## 7. 价值与非目标

| 只交计划 | 交齐量价时 |
|---|---|
| 漏填、可选程序合规 | 拦住超量、偏离价、重复买 |
| 省不了采购额 | 每条能指回本厂的数 |

**v1 不做：** OA/U8 真连接器（界面预留、未接通则禁用）、价格预测、发票入库、供应商质量、生产计划强依赖、自动放行、待审队列、知识图谱。

演示物资（烟煤、石膏、镁铬砖、硅砂）为合成夹具，不写真实客户数。
