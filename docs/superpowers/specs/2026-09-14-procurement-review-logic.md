## 1. 给用户的说法

我们审的是 **这一份物资需求计划里的每一行**：该不该买这么多、该不该这个价、该不该现在再买、该不该由这个人走这个程序。

- **量、价、时** 看本厂经营事实：库存、领用、历史成交、在途采购。来自 OA / 库存 / U8；接口未齐时按同结构导出表接入。
- **合规** 看公司制度：采购管理办法、审批权限、战略物资、招标门槛。来自知识库。
- **判定杠**（几个月算买多、贵百分之几、多少天算重复）写在规则里，模型不得改。

需求计划只说明「他们想买什么」，不是审核依据。没有库存、成交、在途，系统不假装做了量价时。没有制度库（或用户选了「不使用」），系统不假装做了越权判断。每一条结论必须指回用过的那几行事实或那一条制度。

AI 给人建议，人决定过不过。

## 2. 已确认的产品决策

1. 审核骨架是 **量、价、时 + 合规 / 完整性**。发票、入库、供应商质量、价格预测不是 v1。
2. 一次会话审 **一份需求计划**，判断单元是 **每一行**，对齐键：**物资编码**。
3. 事实与制度分开：事实不进 RAG；制度不做加减乘除。
4. 缺哪类证据，关哪一维，写明「未评估」。禁止用模型常识补本厂数字。
5. 接口未齐不改审核逻辑。连接器只换供数方式。
6. 人必须对结论负责。v1 不自动放行采购单。
7. **拉取与上传不是互斥。** 有一份即可开这一维；两份都有则一并对照，数字冲突必须标出，不得偷偷覆盖。计算用上传侧（有上传时），依据里同时写两份来源。
8. **制度是准备页下拉。** v1 只有「采购制度（默认）」与「不使用」。不是每次上传管理办法，也不在 v1 做多库切换。
9. **开始分析** 在计划 + 任一已开对照维时可跑，只评已开维。**完整性审核** 只用计划（facts 空）。二者都进分析页，不跳复核。

## 3. 四类输入（不能混）

| 代号 | 名称 | 回答什么 | 从哪来 | 现在基座 |
|---|---|---|---|---|
| A | 被审件 | 他们想买什么 | OA 需求计划；未接通则上传 | 有文档 / 表格解析 |
| B | 事实对照 | 相对本厂的数，这单乖不乖 | 库存 / U8 / OA；未接通则同结构导出 | **还没有业务系统连接器** |
| C | 制度知识 | 按公司规定该不该这样买 | 知识库 RAG | 已有 SparkiiRAG / 本地 BM25 |
| D | 判定规则 | 杠画在哪里 | 智能体 `rules.yaml` | 无独立规则引擎，先放配置文件 |

合同审核可以「只上传合同」，因为对照物是法规，本来就在 C。  
采购经营审核的对照物是 B，C 代替不了。

## 4. 每一维

### 量

- **依据：** 本行数量 + 当前库存 + 近 N 天领用（界面默认 90，可改为 30 / 180）。
- **算法：** 可覆盖月数 = (库存 + 本次) / (领用天数对应的月均)。默认：大于 4 个月且库存天数大于 30 → 高风险买多；小于 0.5 个月 → 中风险可能不够。领用为 0 → 本维关闭。
- **没有生产计划：** 仍可跑，必须写明「假设未来消耗 ≈ 近 N 天」。
- **取数：** 库存系统 / U8；未接通则导入快照 + 领用流水。

### 价

- **依据：** 本行预估单价 + 该物资近 M 个月本厂成交（界面默认 12，可改为 6 / 24）。
- **算法：** 偏离 = (本次 − 中位价) / 中位价。大于 15% 高，5%–15% 中。样本少于 3 笔 → 只提示、不当高风险。无成交 → 本维关闭。
- **本维不做：** 行情预测、行业指数。
- **取数：** U8 / OA 历史采购；未接通则导入成交表。

### 时

- **依据：** 近 K 天已批准需求、已下订单、在途未入库（界面默认 30，可改为 15 / 60）。
- **算法：** 窗口内有同类且本次仍加量 → 重复采购。
- **取数：** OA 订单；未接通则导入在途表。

### 合规 / 完整性

- **完整性（规则，不检索）：** 缺编码、缺数量、缺单位。只要有计划就能做。
- **合规（RAG）：** 审批权限、战略物资、招标 / 集采门槛。用户选了制度库才跑。
- **不使用制度库：** 只做完整性，合规维关闭。

## 5. 一次分析怎么跑

```
被审件（OA 或上传）
    ↓
取事实：库存 / 领用 / 成交 / 在途（连接器或同结构导入；可与上传并存）
    ↓
按物资编码对齐（确定性 join，不是模型）
    ↓
完整性检查 + 已开维度套规则
    ↓
制度：选用了库才检索；用行上的金额、品类、申请人去 knowledge.search
    ↓
模型只把「已算死的命中」写成发现，每条带依据
    ↓
人采纳 / 忽略 / 升级
    ↓
写入意见 → 导出（审批门）
```

依据字段必须能指到：哪一天的库存、哪几笔成交、哪张在途单、哪一条制度。没有依据的发现不准出现。未命中规则的行不出「价格正常」凑数。

过期：库存快照早于申请日超过 7 天 → 量可跑但标「库存可能不是当天」。成交最后一笔早于 18 个月 → 价降为低置信。

模型**禁止**接触未进入证据包的数字。skill 输入是 join 之后的行快照 + 规则命中。

## 6. 降级（接口未齐也成立）

| 当时有什么 | 系统可以讲什么 | 系统不准讲什么 |
|---|---|---|
| 只有计划 | 填没填全；选了制度库则讲程序 | 买多了、买贵了、重复买 |
| 计划 + 库存 + 领用 | 量 | 价、时 |
| 计划 + 成交 | 价 | 量、时 |
| 计划 + 在途 | 时 | 量、价 |
| 五样齐 | 量价时 + 完整性 | — |
| 再加制度库 | 加上合规 | — |

拉取和上传都有时，两份都进对照。冲突必须进 `conflicts` 并写进依据。**计算用上传侧的数**（没有上传才用拉取），不得假装只有一份。

## 8. 讲给用户时的三句话

1. **审什么：** 这一单每一行的量、价、时，以及程序合不合规。
2. **凭什么：** 量价时凭本厂库存、领用、成交、在途；合规凭本次选用的制度库。
3. **为什么可信：** 数字是业务系统或同结构导出，杠是公布的规则，模型只写成话并标出用过哪几行；缺数就说没审，不编。
