# Pi Agent 1.0.2 → 1.5.0 升级设计

- 日期：2026-11-05
- 状态：待架构审查
- 范围：Sparkii Desktop 内嵌的 `@earendil-works/pi-coding-agent`
- 基线提交：`ae78f5e8f0c9060c51d9a22ae0d9e9c6f9e48021`
- 当前版本：`1.0.2`
- 目标版本：`1.5.0`

## 1. 目标

1. 将内嵌 Pi Agent 内核及锁文件中的 Pi 家族包从 `1.0.2` 升到最新稳定版 `1.5.0`。
2. 保持现有产品语义：工具面、审批边界、会话存储、技能加载、模型配置、进程池和安全路由不变。
3. 验证升级后的 SDK 接口、工具 loadout、`before_agent_start`、会话恢复、Windows 路径和桌面打包仍然成立。
4. 留存一份面向产品的升级说明，列明 1.1.0 至 1.5.0 的实际特性和本产品是否采用。

## 2. 非目标

本轮不启用以下能力，除非兼容性验证证明必须使用且架构审查明确批准：

- codemode；
- MCP；
- `tool_search`；
- virtual models；
- prompt cache warming；
- Pi CLI 自更新器；
- 新的 Pi TUI、主题和交互模式；
- 客户端自动升级或服务端更新策略。

本轮不修改现有 Task Grant、审批策略、Main/Runtime 权威边界，也不让 Pi 工具自行决定权限。

## 4. 设计决策

### 4.1 精确版本钉住

`packages/agent-host/package.json` 使用精确版本 `"1.5.0"`，而不是 caret 范围。

原因：

- Pi 自身已经从宽松范围改为精确内部版本，避免家族包混装；
- Sparkii 是面向最终用户的桌面应用，需要可重复安装结果；
- 后续升级应显式修改版本、锁文件和兼容测试，而不是由一次普通 install 静默漂移。

### 4.2 等价升级优先

升级不得改变现有产品默认行为：

- 继续使用 `customTools + noTools: "builtin" + registerTool + setActiveTools` 装配 saddle；
- 继续显式关闭 Pi cache warming；
- 不注册 codemode、MCP、tool-search；
- 不增加 Pi 侧审批逻辑；
- 所有文件、Shell 和连接器动作仍经 Main 的 Runtime Action / Proposal 路径。

上游新增能力只记录为后续候选，不随内核升级自动开放。

### 4.3 事件兼容

1.2.0 起，`before_agent_start` 在普通用户 prompt 和 `pi.sendMessage(..., { triggerTurn: true })` 启动的自定义 run 上都会触发。

Sparkii 的处理方式：

- 只读取两种事件共有的 `systemPromptOptions`；
- 同时保留事件共同的 `systemPrompt`，供现有 `<available_skills>` 和工作目录 fallback 使用；
- 继续在每次 run 前同步 saddle 工具和系统提示；
- 不假定事件一定包含 `prompt`；
- 新增回归测试，保证 user/custom 两种事件都保留 saddle prompt、技能目录和工作目录；
- 工具同步在所有启动路径上保持精确集合，不泄漏上一鞍工具。

### 4.4 工具与会话

现有 `noTools: "builtin"`、`customTools`、`registerTool` 和 `setActiveTools` 策略保留。

升级后必须证明：

1. 初始无鞍时没有模型可见工具；
2. 配置鞍后工具集合与鞍完全相等；
3. 换鞍新增、撤销和清空工具都生效；
4. `newSession` 和 `switchSession` 后重新应用当前鞍；
5. 恢复含活动工具记录的会话时不泄漏该会话原有 Pi 工具；
6. 未知工具继续 fail closed；
7. `codemode`、`tool_search` 和内置默认工具不会意外出现。

1.5.0 的 `pi-schema` 校验只有普通 JSON Schema 语义。Sparkii 工具定义全部使用普通 JSON Schema 或经过现有 JSON Schema 转换器生成，不使用 `Type.Refine()`、`Type.BigInt()`、`Type.Undefined()`、codec 或 `Format.Set()`。

验证不能只调用工具定义的 `execute()`，因为那会绕过 Pi 的参数校验、coercion 和错误格式化。兼容测试直接使用 `@earendil-works/pi-ai@1.5.0` 的公开 `validateToolArguments()`：

- missing required 不进入工具；
- `additionalProperties: false` 拒绝额外字段；
- 数字字符串和单值到数组按 1.5 约定 coercion；
- 错误文本包含字段路径、expected 和 got；
- 连接器提案收到的是验证和 coercion 之后的冻结参数。

`@earendil-works/pi-ai` 只在 `packages/agent-host` 增加为同版本的 devDependency，用于真实验证路径测试，不让产品代码直接依赖新的 Pi 内部包。

### 4.4.1 图片处理边界

Sparkii Main 已经在发送图片前用 Electron `nativeImage` 完成尺寸和大小压缩。Pi 的 prompt 规范化仍会读取 `imageAutoResize`；开启时会加载 `image-resize-worker.js` 和 Photon WASM。

为避免重复处理并避免桌面 bundle 依赖未交付的 worker/WASM，Pi agentDir 的设置显式使用 `imageAutoResize: false`。已支持的 PNG/JPEG/GIF/WebP 图片直接作为 inline image 进入 prompt；Sparkii 的附件入口继续负责压缩和格式规整。

这不把 Pi 内部图片自动缩放声明为支持能力。升级报告必须明确记录：Pi worker/WASM 动态路径未交付、未启用，关闭 auto-resize 是有意的产品边界。

### 4.5 模型与 provider

- 继续只通过 `models.json` 写自定义 provider，通过 `setRuntimeApiKey` 注入凭据。
- 不启用 Azure，因此不做 provider key 迁移。
- `kimi-coding` 使用 1.3.0 新地址 `https://api.kimi.com/coding/v1`。保存设置和写 `models.json` 时，对已知旧地址 `https://api.kimi.com/coding` 做一次可测试的规范化；读取 settings 时也先规范化，避免 UI 和 runtime 展示不同地址。
- 内置模型目录变化和默认模型变化不会覆盖用户显式 `activeProviderId/defaultModel`。
- 思考等级仍由现有 UI 和 `getAvailableThinkingLevels()` 动态提供。
- 1.5.0 新增的 GPT-6.1 Terra 等模型只在内置 provider 列表/模型目录中体现，不改变 Sparkii 默认 DeepSeek 配置。

### 4.6 会话与设置兼容

- 会话格式保持版本 3，不编写数据迁移。
- 1.2.0+ 新增的字段按可选字段处理，未知字段不主动删除。
- 增加“1.5 写入的可选字段/条目仍能被当前读取投影处理”的测试；回退到 1.0.2 的风险在升级报告中记录，不做伪造迁移。
- `settings.json` 继续关闭 cache warming，并保留 Pi 自行管理的其它设置。
- `auth.json`、`models.json`、`sessions/` 仍位于 Sparkii 的 `pi-agent` 目录。
- 1.2.0 的 Windows `auth.json` 锁修复直接采用，不增加应用层重试补丁。

### 4.7 打包

继续用 esbuild 把 Pi SDK 内联到 `dist-electron/pi-runtime/utility-entry.js` 和 `fork-entry.js`。

验收：

- `build:main` 成功；
- 两个入口产物存在；
- SDK smoke 成功；
- 在 Node 子进程中真实启动 `fork-entry.js`，完成 ready → get_state → abort → exit 握手；
- 通过模拟 `process.parentPort` 加载 `utility-entry.js`，完成 ready 与一次命令响应；
- 检查 bundle 中没有未解析的 `@earendil-works/*` 外部 import；
- 断言 Pi settings 中 `imageAutoResize === false`；
- bundle 体积记录在升级报告中；
- 若出现 `.wasm`、worker 或动态依赖错误，优先修正 esbuild 配置；不在未证明的情况下把 Pi 变成运行时外部依赖。

## 5. 错误处理与回滚

- 依赖安装失败：保留 `main` 不动，删除升级分支或恢复 lockfile。
- SDK 类型不兼容：只做接口适配，不放宽安全边界。
- 工具集合不等：阻断升级，修正装配后才继续。
- 会话恢复失败：阻断升级，补兼容测试；禁止静默创建新会话掩盖问题。
- 打包失败：阻断升级，先定位具体 bundle 依赖。
- 全量测试失败：阻断升级；确认为上游行为变化时记录并修正产品适配。

回滚以单个升级分支为边界。由于会话版本未变，回滚到 1.0.2 不需要数据迁移；Pi 新增的未知 JSONL/settings 字段应允许被旧版本忽略。该假设必须有 1.5 写入、当前读取路径仍可投影的测试证据，并在报告中记录 1.0.2 回退验证的边界。

## 6. 验收标准

1. 实际解析的 `@earendil-works/pi-coding-agent` 和 Pi 家族包版本均为 `1.5.0`。
2. 现有工具装配、换鞍、会话替换、技能提示和 cache warming 关闭测试通过。
3. 新增 user/custom `before_agent_start` 和恢复会话工具面测试通过。
4. Agent Host、桌面渲染端、Electron 主进程和 UI 包类型检查通过。
5. ESLint 为 0 error。
6. 完整 Vitest 套件 0 failure。
7. 桌面主进程构建与 Pi SDK smoke 通过。
8. `fork-entry.js` 和 `utility-entry.js` 实际启动 smoke 通过。
9. 升级文档列明 1.0.3–1.5.0 的产品相关特性、采用/不采用决定和兼容处理。
